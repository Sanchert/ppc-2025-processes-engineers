## 1. Введение
Рассматривается задача суммирования элементов вектора. Работа предполагает разработку последовательной и MPI-параллельной версий алгоритма, сравнение их производительности на разных размерах входных данных и разном числе процессов.

## 2. Постановка задачи
На вход программе подается целое число — размер вектора N. Требуется найти сумму всех его элементов.

**Примененные оптимизации**\
Вместо создания и физического хранения всего вектора, его элементы задаются простой формулой, зависящей от индекса элемента `i % 256`. Это дает несколько преимуществ:
1. Прямой достук к данным из любой части программы;
2. Детерминированност данных;
3. Отсутствие дополнительных расходов на рассылку.
4. Оптимизация памяти: вместо `O(N)` — хранение вектора, `O(1)` — длина вектора (одно число)

**Ограничения:**
- `N` является беззнаковым целым 64-биным числом
- Элементы вектора являются целыми 32-битными числами

## 3. Описание базового алгоритма (последовательная версия)
Последовательный алгоритм — последовательное вычисление элементов и накопление их суммы в переменную. Время выполнения `O(N)`.
```cpp
for (std::uint64_t i = 0; i < size; i++) {
    total_sum += i % 256;
}
```

## 4. Схема распараллеливания
**Описание действий роцессов `0-N`:**
1. Каждый процесс получает размер входного вектора.
2. Каждый процесс на основе общего числа поцессов, собстенного номера и размера вектора вычисляет начальный и конечный индексы суммирования (диапазон). По индексам диапазона вычисляются значения элементов и пибавляются к локальной сумме.
3. Все локальные суммы суммируются в одну глобальную через MPI_Allreduce, результат доступен у всех процессов.

## 8. Заключение
- **Корректность:** алгоритм успешно обрабатывает векторы различных размеров — от минимальных до максимальных.
- **Производительность:** последовательная версия демонстрирует высокую эффективность, выполняясь за ~0.125 секунды на одном процессе.
- **Масштабируемость:** при увеличении числа процессов (2 - 8) наблюдается рост скорости работы, однако эффективность снижается из-за низкой вычислительной сложности по сравнению с накладными расходами MPI.

## Приложение
```cpp
bool KolotukhinAElemVecSumMPI::RunImpl() {
  int p_id = -1;
  int p_count = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &p_id);
  MPI_Comm_size(MPI_COMM_WORLD, &p_count);

  std::size_t input_size = GetInput();

  auto uint_pid = static_cast<std::uint64_t>(p_id);
  auto uint_p_count = static_cast<std::uint64_t>(p_count);
  
  std::uint64_t min_part = input_size / uint_p_count;
  std::uint64_t rem = input_size % uint_p_count;
  std::uint64_t proc_size = min_part + (std::less<>()(uint_pid, rem) ? 1 : 0);
  std::int64_t local_sum = 0;
  std::uint64_t start = (min_part * uint_pid) + (std::less<>()(uint_pid, rem) ? uint_pid : rem);
  std::uint64_t end = start + proc_size;
  for (std::uint64_t i = start; (i < end); i++) {
    local_sum += i % 256;
  }
  
  std::int64_t global_sum = 0;
  MPI_Allreduce(&local_sum, &global_sum, 1, MPI_INT64_T, MPI_SUM, MPI_COMM_WORLD);
  
  GetOutput() = global_sum;
  return true;
}
```

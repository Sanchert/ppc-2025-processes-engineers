## 1. Введение
Рассматривается задача суммирования элементов вектора. Работа предполагает разработку последовательной и MPI-параллельной версий алгоритма, сравнение их производительности на разных размерах входных данных и разном числе процессов.

## 2. Постановка задачи
На вход программе подается вектор из целых чисел длины N. Требуется найти сумму всех его элементов, это значение подается на выход.

**Ограничения:**
- N и элементы вектора являются беззнаковыи целыи 32-биными числами
- Программа должна корректно работать на одном и нескольких процессах

## 3. Описание базового алгоритма (последовательная версия)
Последовательный алгоритм — проход по всему вектору в цикле и накопление суммы в переменную. Время выполнения `O(N)`.
```cpp
for (std::uint64_t i = 0; i < input_vec.size(); i++) {
    total_sum += input_vec[i];
}
```

## 4. Схема распараллеливания
**Краткое описание**
1. Корневой процесс разделяет входной вектор между всеми имеющимися процессами через MPI_Scatter
2. Каждый процесс считает сумму своей части
3. Все локальные суммы объединяются в одну глобальную через MPI_Allreduce, результат доступен у всех процессов.

**Процессы:**
```0```: единственный процесс, что формирует, содержит и рассылает входные данные и их размеры.
```0-N```: принимают чать входных данных считают локальные суммы, отправляют их в глобальную сумму.

## 8. Заключение
- Корректность: реализованный алгоритм успешно справляется с обработкой различных объемов данных.
- Производительность: время выполнения последовательной версии составляет примерно 0.16 секунд, что подтверждает эффективность вычислений на одном процессоре. 
- Масштабируемость и эффективность: при увеличении числа процессов — 2, 4, 8 — наблюдается снижение скорости — снижение эффективности, вероятно, связано с низкой затратностью вычислений по сравнению с накладными расходами MPI.

**Основные выводы:**

В задаче суммирования элементов вектора простая арифметическая операция не является «тяжелой», и накладные расходы на коммуникацию в MPI существенно влияют на общий результат.

Таким образом, реализация показывает, что при простых арифметических операциях и больших объемах данных выгода от распараллеливания может быть ограниченной из-за дороговизны коммуникационных операций MPI.

## Приложение
```cpp
bool KolotukhinAElemVecSumMPI::RunImpl() {
  int p_id = -1;
  int p_count = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &p_id);
  MPI_Comm_size(MPI_COMM_WORLD, &p_count);

  std::vector<int> input_data;
  std::size_t input_size = 0;

  if (p_id == 0) {
    input_data = GetInput();
    input_size = input_data.size();
  }

  MPI_Bcast(&input_size, 1, MPI_UINT64_T, 0, MPI_COMM_WORLD);
  
  int base_size = input_size / p_count;
  int my_size = base_size;
  if (p_id == 0) {
    my_size += input_size % p_count;
  }

  std::vector<int> local_data(my_size);

  MPI_Scatter(input_data.data(), base_size, MPI_INT, local_data.data(), base_size, MPI_INT, 0, MPI_COMM_WORLD);

  if (p_id == 0 && input_size % p_count != 0) {
    int remainder_start = base_size * p_count;
    int remainder_size = input_size % p_count;
    for (int i = 0; i < remainder_size; i++) {
      local_data[base_size + i] = input_data[remainder_start + i];
    }
  }

  std::int64_t local_sum = std::accumulate(local_data.begin(), local_data.end(), 0LL);

  std::int64_t global_sum = 0;
  MPI_Reduce(&local_sum, &global_sum, 1, MPI_INT64_T, MPI_SUM, 0, MPI_COMM_WORLD);

  GetOutput() = global_sum;

  return true;
}
```
